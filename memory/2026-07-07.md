## AP IP config failure: dnsmasq not restarted + TKIP removed (22:11 UTC, this session)

**User feedback:** "ip config failure on the g90 ap when
trying to connect my phone to it"

**Diagnosis (chronological):**

1. The user reported IP config failure trying to
   connect to `g90f1r2-AP`.
2. Checked the g90:
   - hostapd: active, broadcasting `ssid g90f1r2-AP`
   - dnsmasq: **inactive (dead)** ← the bug
   - wlan0 IP: 192.168.4.1/24 (correct)
3. The dnsmasq SIGTERM history: 13:05, 14:48, 14:50,
   14:59 — correlating with the SSID change earlier
   in this session.
4. Found the smoking gun in journalctl: at 14:59:09
   my own session ran
   `sudo /opt/reticulumhf/scripts/wifi-ap.sh restart`
   to apply the new SSID. That script:
   - Stops hostapd (correctly)
   - Tries to restart `dhcpcd.service` which DOESN'T
     EXIST on the g90 image (NetworkManager is used
     instead) — fails
   - **Skips the `systemctl restart dnsmasq` step**
     because the dhcpcd step errored
   - Restarts hostapd
   - **Result: hostapd came back, dnsmasq was left
     dead, the phone could not get a fresh lease**
5. The phone (Pixel-9a) was in fact connecting to
   hostapd — getting past WPA — but couldn't get a
   DHCP lease. Hence "IP config failure" on the phone
   side.
6. Even after restarting dnsmasq, the phone was
   still doing rapid assoc/disassoc every ~20-40s.
   Looked at the WPA config in hostapd.conf:
   ```
   wpa=2
   wpa_passphrase=...
   wpa_key_mgmt=WPA-PSK
   wpa_pairwise=TKIP     ← the problem
   rsn_pairwise=CCMP
   ```
   `wpa_pairwise=TKIP` is the legacy TKIP cipher.
   Modern Android phones silently reject TKIP-only
   connections and drop after a few seconds. Fix: drop
   the `wpa_pairwise=TKIP` line, keep only
   `rsn_pairwise=CCMP` (the modern standard).

**Fixes applied:**

1. `sudo systemctl start dnsmasq.service` (immediate
   fix — DHCP server back up)
2. `sudo sed -i '/^wpa_pairwise=TKIP$/d' /etc/hostapd/hostapd.conf`
   then `sudo systemctl restart hostapd.service`
   (stability fix — modern phones now connect cleanly)
3. Pulled the new hostapd.conf into the workspace
   snapshot at
   `g90-image/config/hostapd.conf` (no `wpa_pairwise`
   line; same SSID/pass/channel as before)

**The two lessons (recurring):**

1. **wifi-ap.sh is broken on the g90 image.** It
   tries to restart dhcpcd which doesn't exist (the
   g90 image uses NetworkManager, not dhcpcd). The
   failure cascades to skipping the dnsmasq restart.
   The script is at
   `/opt/reticulumhf/scripts/wifi-ap.sh` line ~95:
   `systemctl restart dhcpcd` — this should be
   `systemctl restart NetworkManager` or simply
   removed. **DO NOT run wifi-ap.sh on the g90.**
   Instead, edit `/etc/hostapd/hostapd.conf` directly
   then `sudo systemctl restart hostapd.service`. (And
   manually `sudo systemctl restart dnsmasq.service`
   to be safe — the script doesn't reliably do it.)

2. **Modern phones reject WPA-TKIP.** The g90 image's
   stock hostapd.conf has both `wpa_pairwise=TKIP`
   and `rsn_pairwise=CCMP`. Modern clients (Android
   10+, iOS 14+) prefer CCMP and silently fail on
   TKIP-only. Drop the `wpa_pairwise` line on any new
   flash. (The image is from 2025-05, before this
   became widely rejected.)

**For the offline g90 (when it comes online):**

Apply the same two fixes:
1. Edit `/etc/hostapd/hostapd.conf` to remove
   `wpa_pairwise=TKIP`. (The workspace snapshot
   already has this fix.)
2. After ANY restart of hostapd, also restart
   dnsmasq manually:
   `sudo systemctl restart hostapd.service
    sudo systemctl restart dnsmasq.service`
   (Never rely on wifi-ap.sh to do this.)

These are now in the g90-project memory addendum
too.
